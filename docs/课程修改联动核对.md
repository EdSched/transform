# 课程修改联动核对（开发者内部文档）

目标：课程一改，教室占用、总务通知、课程安排、今日页、教室看板、学生课表、课程表都必须跟着变，不靠人记得去点。
范围：全仓库所有会写 `courses` / `course_sessions` 的入口（用 `grep` 搜 `rest/v1/courses`、`rest/v1/course_sessions`、`sbUpdate('courses'…` 等得到，已排除 `admin/modules/*` 空壳；`teacher/`、`student/`、`salary/` 没有任何写这两张表的代码）。

## 一、联动机制（先看这个，表里的「怎么变」都指向这里）

| 对象 | 怎么跟着变 | 依据 |
|---|---|---|
| 每周占用（`recurrence='weekly'`） | 不改库。`sched/common.js` 的 `linkCourseBookings` 按每一回的日期 / 时间在内存里重算；`loadCourseLink` 读 `course_sessions` | 既有；`tests/health-check.test.js` 用到 |
| 单日占用（`recurrence='once'`，某一回换了教室）·日期变 / 休讲 / 删除 | 数据库触发器 `course_session_release_room` 释放（并给总务留 `reason='released'` 提示） | `seed/course_session_release_trigger.sql`（既有） |
| 单日占用·**时间变** | **PR-2**：前端 `linkCourseBookings` 立刻按这一回时间显示；数据库触发器 `course_session_sync_once_time` 同步存库的时间，撞教室则留 `reason='blocked'` 提示 | `seed/course_session_time_sync_trigger.sql`；`tests/once-time-link.test.js` |
| 总务通知（`sched_change_log.action='room_coord'`） | `shared/session-room-confirm.js` 的 `srmCoordWrite`（同一门课同一回只留一条）。**PR-1**：课程编辑保存后 `srmOpen({auto:true})` 自动写；**PR-3**：其余入口的弹窗点「完成」时，没处理的被占回自动写 | `tests/session-coord.test.js` |
| 今日页 / 教室看板 / 冲突检查 / 课程安排 | 都读 `linkCourseBookings` 或 `crvSessionAwareBks`（`shared/course-room-view.js`）后的结果，按每一回算 | `sched/today.html`、`board.html`、`index.html`、`booking.html`、`entry.html`、`vip.html`、`courses.html`、`meeting.html` 都调用 `loadCourseLink(); linkCourseBookings(...)`；管理端面谈排教室 / 老师端 VIP 预约调用 `crvSessionAwareBks` |
| 学生课表 / 课程表 | 直接读 `course_sessions`（`student/study.js`、`sched/timetable.html`），改了即变。课程表画法不动 | 代码阅读 |
| 体检（**PR-3**） | `sched/health.js` 的 `hcCheck`：遗留占用 / 时间不一致 / 上课日没占用 / 教室重叠，兜底发现以上任何一处漏掉的情况 | `tests/health-check.test.js` |

## 四、仍然存在的限制（没有悄悄略过）

1. 旧编辑弹窗里只改周几 / 开课日 / 回数、不点「重新生成课次」时，单回不会重排（该弹窗一直如此，已有单独按钮），所以这种情况下占用和显示都没变，也不需要通知。
2. 体检第 4 项（教室重叠）的「一键修复」只能给涉及的**课程**写协调通知；两条都不是课程的占用（如外借 × 会议）需要人工判断保留哪条。
3. 体检第 3 项（上课日没占用）的「一键修复」是通知总务安排，不是自动挑教室。
4. 数据库两个触发器（释放 / 时间同步）需 Sensis 手动执行 SQL 才生效；没装之前，单日占用的显示靠前端已经是对的，库里的时间靠体检第 2 项一键修复。
