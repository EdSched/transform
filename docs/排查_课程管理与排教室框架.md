# 排查报告：课程管理与「排教室框架」（每周占用）

> 范围：只读代码排查，**没有改任何功能**。依据 `main`（含任务 A 的改动）里的代码；库里的实际数据我看不到，凡是要看数据才能确定的，标「需要 Sensis 确认」。
> 结论先说：**设计意图"所有课程调整都在课程安排里改"已经落实了大半，但还有三处没落实到位**（见第 5 节）；**每周占用这个框架不能去掉，但它里面的「星期 / 时间 / 起止日期」已经没用了，只剩「这门课平时用哪间教室、绑哪个会议账号」有用**。

## 1. 数据流总图

### 1.1 三份数据，谁是唯一来源

| 数据 | 存在哪 | 谁写 | 谁是"唯一来源" |
|---|---|---|---|
| 课程本身（名字、老师、专业、星期、开课日、回数、时间、休讲日） | `courses`（排课读的是视图 `sched_course_v`） | 管理端「课程安排」；排课的「课程管理」只能写其中几列（见 1.3） | **课程信息的唯一来源 = `courses`** |
| 每一回（第几回、哪天、几点、休讲） | `course_sessions` | 管理端「课程安排」（改期 / 休讲 / 新增 / 撤回）；排课「调整某一天」里的「改时间 / 休讲」也写它 | **"哪一天上课"的唯一来源 = `course_sessions`**（有单回数据的课） |
| 教室占用 | `sched_bookings` | 见下表 | **"在哪间教室"的唯一来源 = `sched_bookings`** |

### 1.2 `sched_bookings` 里和课程有关的两种记录（`kind='course'`）

| 记录 | 含义 | 谁写 | 谁读 |
|---|---|---|---|
| 每周占用 `recurrence='weekly'` | "这门课平时用哪间教室"（还可带会议账号 `uses_meeting` / `meeting_account_id`）；`manual_off_dates` = 某天让位给临时占用 | 只有排课「排教室」`assignRoomOnly`（先删后建）、「清空教室」删；会议账号设定页 `meeting.html` 改绑定 | 见第 3 节 |
| 单日（临时）占用 `recurrence='once'` | "这一回换到了另一间教室" | 管理端「课程安排」换教室（`crvSwapRoom`）；排课「调整某一天 → 换教室」；**总务新面板「安排教室」（任务 A）** | 同上；**只有那天这门课真有没休讲的单回才算数**（`courseOnceOrphan` / `srmBlockers` / `crvRoomStatus` / 数据库触发器 `sched_booking_span_on` 一致） |

### 1.3 排课系统读课程时的「跟着管理端走」层

`sched/common.js` 的 `loadCourseLink` + `linkCourseBookings`：页面加载时在**内存里**把每周占用的时间 / 起止日期 / 星期改成"课程当前的"，并且规定"这一天有单回才占教室"。**不写库**。所以：

- 排课系统里的页面（看板 / 今日 / 冲突检查 / 预约录入 / VIP 预约 / 会议账号）看到的是**按单回算**的占用——正确。
- 但库里每周占用记录自己的 `weekday / start_time / end_time / start_date / end_date` 不会被更新，仍是**排教室那天的旧值**。凡是**没走这一层**的地方，读到的就是旧值（见第 4 节）。

## 3. 每周占用这个「框架」到底被谁依赖

| 依赖方 | 是否依赖每周占用 | 依赖的是哪个字段 |
|---|---|---|
| 「排教室」列表的"已排 / 未排 / 排哪间"、排课提醒（`schedulingReminders`、`isWeeklyCourseBk`） | **是** | 这门课有没有 `kind=course, recurrence=weekly` 记录；`room_id` |
| 教室看板 / 今日 / 冲突检查 / 预约录入 / VIP 预约（经链接层） | 是 | `room_id`、`course_id`；时间和日期**已改读单回**，不再用记录自带的 |
| 管理端课程安排上每回的教室显示（`crvFixed` / `crvRoomOn` / `crvSessionState`） | **是** | `room_id`（"固定教室"）、`weekday`（挑哪条）、`manual_off_dates`；没有每周占用 = 全部显示"未排教室" |
| 空教室计算（`crvRoomStatus`、`srmBlockers`、总务新面板 `coordBlockersOf`） | 是 | `room_id`；时间 / 日期同样改读单回 |
| 会议账号占用（`meeting.html`、`accountConflicts`） | **是，强依赖** | `uses_meeting`、`meeting_account_id`（会议账号是挂在每周占用上的） |
| 数据库防撞触发器（`sched_bookings_check_overlap` 等，见 `seed/room_conflict_by_session.sql`） | 是 | `room_id`、`course_id`；有单回的课按单回算，**没有单回的老课仍按 `weekday / start_date / end_date / start_time / end_time`** |
| **老师端 VIP 预约 `vrpLoad`、管理端 `bkvOnDate`（面谈排教室）** | **是，而且用的是旧规则** | **`weekday / start_date / end_date / start_time / end_time`（原始值）**——这是第 4 节问题的来源 |
| 课程表 `timetable.html` 画课表格子 | **否** | 完全不用占用，用 `courses` 的星期 + 起止日期 + 休讲日（`expand(c)`） |
| 学生课表 / 出勤 / 作业 | **否** | 只用 `course_sessions` |

### 判断：**保留**，但把它的定位说清楚

- **不能去掉**：会议账号、「已排 / 未排」、课程安排上每回的教室显示、空教室计算都挂在它上面。去掉等于要重建一套"课程默认教室"表，并迁移会议绑定，风险大、收益小。
- **可以瘦身（不急，等 Sensis 拍板）**：它里面的 `weekday / start_time / end_time / start_date / end_date` 已经被"跟着课程走"层盖住，**唯一还在用旧值的是老师端 VIP 预约和管理端面谈排教室**（第 4 节）。把这两处也改成走单回，库里这几列就可以不再维护。
- 去掉的风险（如果以后真要去）：① 会议账号绑定丢失；② 没有单回的老课没有任何占用依据；③ 数据库触发器要同步改。

## 4. 课程表走不走这个框架：有两套来源，会不一致

| 展示 | 日期 / 时间来源 | 教室来源 |
|---|---|---|
| 排课系统 · 教室看板 / 今日 / 冲突检查 / 预约录入 | **单回**（`course_sessions`，经链接层） | `sched_bookings` |
| 排课系统 · **课程表 `timetable.html` 的格子** | **规则推算**：`courses` 的星期 + 开课日~结课日 + 休讲日（`expand(c)`）。**不读单回** | 不显示教室（只有「调整说明」文字里读） |
| 排课系统 · 课程查询 `courses.html` | 单回（+ 规则推算兜底） | `crv*`（与课程安排同算法） |
| 管理端 · 课程安排 / 出勤 / 课程列表 | 单回 | 课程安排上用 `crv*` |
| 学生端课表 | 单回 | 无教室 |
| 老师端 VIP 预约 / 管理端面谈排教室 | **规则推算**（每周占用记录里的 `weekday / 起止日期`），再扣 `courses.skip_dates` | `sched_bookings` |

**会出现不一致的场景**（代码层面确定会发生，具体哪门课发生要看数据）：

1. **改了某一回的日期 / 时间**：课程表格子**仍显示在原来那天**（只在「调整说明」里写"原 → 现"）；学生课表、教室看板已经是新日期。——这是课程表的设计取舍（课表是"标准版"+调整说明），但要让负责人知道。**需要 Sensis 确认这是不是有意的。**
2. **课程整体改了上课星期**（例如理数从周一改到周五）：看板 / 今日按单回，显示周五；但每周占用记录里 `weekday` 还是 1，**老师端 VIP 预约和管理端面谈排教室会认为"周一的教室 E 还被理数占着，周五的 E 空着"**。——这和任务单里"面谈被理数占着"的现象吻合，**很可能是真正的源头之一**（总务看到的"被占"其实是旧星期的每周记录，而不是单日遗留占用）。**需要 Sensis 用库里数据确认**：理数那条每周占用的 `weekday` 是不是 1。
3. **单回遗留占用**（任务 A 处理的）：改期 / 休讲后，换教室时建的单日占用没人删。排课页面自己判断时已经不算它们（`courseOnceOrphan`），所以**不会**让教室看板显示"被占"；但数据库里还在，卡片 / 弹窗里会列出来让人迷惑。任务 A 已补上"改期 / 休讲 / 撤回自动清"和"一键清理"。
4. **每周占用分段排**（一门课同一星期排了多条）：链接层不会改它的时间 / 星期，只看"有没有单回"。如果课程星期改了而占用的 `weekday` 没变，这条占用就**在新的上课日不显示**——"理数在 today 上不显示"这类问题很可能同源。**需要 Sensis 确认**：理数在库里有几条每周占用、`weekday` 各是几。

## 5. 建议清单

| 功能 | 现状 | 建议 | 原因 |
|---|---|---|---|
| 排教室（每周占用） | 总务建 / 重排 | **保留** | 框架唯一入口 |
| 清空教室 | 总务 | **保留** | 总务职责；建议加二次确认已有 |
| 调整某一天 · 换教室 | 总务（旧弹窗） | **保留，但最终并入新「安排教室」面板**；旧弹窗只留给"主动去调某一天的教室"的场景 | 避免两个入口两套逻辑（现在两处写占用的代码是同一套思路复制的） |

| 调整某一天 · 休讲 | 同上 | **删除** | 只标休讲不顺延，和课程安排「休讲并顺延」行为不一致 |

| 课程管理 · 校区 / 方式 / 会议链接 / 预估人数 | 可改 | **保留这几项** | 总务排教室、配会议链接真的要用；校区和方式写的是课程字段但不动日期，风险小。**需要 Sensis 确认**是否同意"校区 / 方式"仍由总务改 |
| 课程管理 · 批量改校区 / 方式 | 可批量 | 保留（同上） | 同上 |
| 课程管理 · 移出 / 恢复排课 | 总务 | 保留 | 属于"这门课要不要排教室" |

| 老师端 VIP 预约 / 管理端面谈排教室用旧规则 | 如上 | **建议改成按单回判断**（复用 `srmBlockers` 的算法） | 第 4 节场景 2：会出现"明明空着却显示被占"或"显示空着其实被占" |

### 「有限修改功能还要不要」的判断

- **总务真的需要**：排教室、清空教室、换某一天的教室、移出 / 恢复排课、校区 / 方式 / 会议链接 / 预估人数、会议账号绑定、教室占用录入。这些都是"教室和会议资源"，不动课程日期。
- **应该只在课程安排里做**：上课时间、某一回的日期 / 时间、休讲、顺延、换老师、改回数 / 星期 / 开课日。
